# Fran 近战动作与特效侦查总览

审查日期：2026-08-15

## 1. 本轮任务边界

这轮只做资料侦查与设计判断，不修改 Fran 的武器、弹幕、玩家移动或特效代码。

本轮检查对象：

- Mod of Redemption 本地源码 `RedemptionAlpha`，版本 `0.8.0.4200`。
- Calamity 本地源码 `CalamityMod`，版本 `2.2.2`。
- Homeward Journey 本地 `ContinentOfJourney.tmod` 解包源码，版本 `0.8.70.88`。
- 官方网页只用于取得公开武器目录、分类和说明；当网页与本地源码冲突时，以用户指定的本地版本为实现依据。

静态源码可以证明动作状态、碰撞、绘制调用和玩家速度写入，但不能证明实际画面已经好看、打击感已经舒服，也不能代替单人/多人实机测试。

## 2. 最重要的结论

三者不是同一条路线。

| 模组 | 动作系统的核心 | 特效系统的核心 | 最强项 | 主要代价 |
|---|---|---|---|---|
| Calamity | 可复用的持握弹幕基类、明确的启动/挥击/收招相位、连续缓动曲线 | Primitive Trail、Shader、武器形变、历史轨迹 | 动作连续、轨迹可调、武器与手臂关系稳定 | 高级武器常把移动、攻击、发射物和特效耦合得很深 |
| Redemption | 很薄的真近战基类，大量武器各自编写状态机 | 逐帧效果贴图、关键帧事件、粒子缓冲、Additive、震屏、地面冲击传播 | 锤类重击和“命中时发生什么”特别有重量 | 复用度较低，很多动作逻辑散在单武器文件中 |
| Homeward Journey | 普通剑多保留原版挥舞；腰带用全局系统统一替换成蓄力大挥砍 | 通用斩痕贴图、Additive 多层叠画、按武器贴图自动取色 | 用一套规则覆盖大量原版/模组剑，系统性很强 | 代码非常集中且含大量武器兼容分支，不适合直接照抄 |

对 Fran 最适合的组合不是三选一，而是：

1. 用 Calamity 的“动作相位 + 连续缓动 + 线段碰撞”作为左键骨架。
2. 用 Redemption 的“关键帧事件 + 重击分层 + 地面反馈”构成打击感。
3. 用 Homeward Journey 的“统一规则覆盖一整套武器行为”思路管理传奇武器的全流程升级，但不采用它的巨型通用斩痕作为全部攻击的视觉答案。

## 3. 对当前 Fran 方向的直接判断

用户说当前特效和推动不符合意愿，这个判断成立。问题不只是颜色或粒子数量，而是动作、判定、特效没有使用同一套语义：

- 斩击应当沿着师傅的真实刀路生长，而不是动作完成后在附近出现一个无来源的光团。
- 重斩应当先有蓄力或加速，再在接触帧产生压缩、亮边、爆点和余波。
- 突刺应当是刀尖沿鼠标方向推进，判定和尾迹都服从同一条轴线。
- 普通左键的任何一段都不能强制推动玩家或敌人；攻击姿态不能偷偷成为位移技能。
- 冲刺、屏障、治疗等战术技能应拥有各自独立的视觉语言，不能继续借“多发弹幕”代替语义。

## 4. 建议给 Fran 建立的基础层

后续重做时，先建立五个可复用层，而不是立刻逐招堆弹幕：

### 4.1 动作层

统一处理启动、有效攻击、收招、连段编号、攻击速度换算、鼠标朝向锁定和复合手臂姿势。

### 4.2 轨迹层

每一段攻击只声明起始角、结束角、半径/前伸距离、缓动曲线和有效窗口。批砍、回旋、强化斩、突刺应是四个不同的轨迹配置，而非四套互不相干的 AI。

### 4.3 判定层

弧形斩击使用刀身线段或扫掠线段；突刺使用从手部到刀尖的轴向线段。视觉轨迹、刀身位置与碰撞必须来自同一组参数。

### 4.4 特效层

把特效分为预兆、刀路、接触、余波四段。每段都绑定动作时间，而不是随机生成。

### 4.5 事件层

只有事件层能生成爆炸、地面裂波、命中特写、震屏或声音。普通挥动不产生与动作无关的自主弹幕。

## 5. 明确禁止吸收的做法

- 不复制三模组的贴图、音频、Shader 文件或受保护代码；这里只学习架构和表现方法。
- 不把 Earth 的敌人强制位移带入 Fran 左键。
- 不把 Exoblade 特殊突进中直接改写玩家速度的做法带入普通左键。
- 不把 Redemption 的 Ukonvasara 旋转玩家、强制向鼠标移动或垂直砸落带入普通左键。
- 不用 Homeward Journey 那种一张通用大斩痕覆盖所有招式；Fran 的四段左键必须能仅凭轮廓就分辨。
- 不以“弹幕多、粒子多、屏幕更亮”代替动作可读性。
